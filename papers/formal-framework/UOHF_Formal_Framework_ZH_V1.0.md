# 摘要

人体研究分布在解剖学、生理学、医学、康复、运动科学、行为科学、临床信息学与多尺度计算建模等不同领域。这些领域能够详细描述结构、过程、疾病、能力、活动、干预与结局，但它们本身并不会自动形成一套统一形式，用来说明：一个具体人的身体能力在某项明确的内部或外部需求下如何被调用；这种调用是否适合这个人及其当前情境；随之产生了什么结果、代价、边界与恢复变化；以及新的证据和行动应当如何更新这个人的长期模型。

本文在人体功能统一本体（Unified Ontology of Human Function，UOHF）中建立人体功能的形式化框架，并保留根定义：人体功能是身体为满足内部与外部需求而被适当调用的能力。本文严格区分人体功能能力、功能调用模式规格、实际调用过程、表现、测量、推断、问题假设和信息表示，防止把现实对象、证据和结论混写为同一对象。

本文提出一套类型化数学结构，包括：完整人体潜在状态、人体功能能力域、需求与情境说明、调用模式规格空间、能力到调用模式的可实现性算子、事前适当调用模式域、实际调用过程、潜在结果、预测结果、观察结果、证据、限制因素假设、受治理行动以及长期状态更新。核心的“需求有界可实现性”判据用于界定：对一个具体的人、时间与情境而言，某项需求在本体真实层面何时可以被适当地满足——至少存在一个调用模式规格，它能够由当前能力实现，具有达到要求的操作可达性与可靠性，满足事前的个体化安全、负荷、维持和恢复约束，并且至少兼容一个可接受的潜在结果。

运行系统不能直接观察完整真实状态，因此只能输出证据层面的判断：支持、不支持或证据不足。本文进一步将问题假设与证据状态分离。能力覆盖失败、功能调用困难以及其他或残余解释可以同时存在；支持、减弱、矛盾、未评估、证据不足和无法确定，则描述这些假设当前的认识状态。本文还区分功能能力锚点、身体结构锚点、身体过程锚点、观察评估锚点、约束锚点与行动锚点，并明确锚点不能自动等同于病因诊断。

受治理决策层使用行动特异的证据阈值，并同时检查安全、专业权限、同意、作用范围、可行性、停止条件、复评需求和反馈。爬楼膝痛与运动后恢复案例展示这套框架如何从表现形成可验证假设和允许的下一步，而不把症状自动转换成诊断。本文贡献的是一套面向实现、可验证和可审计的形式框架与研究路线，不是已经完成的完整人体方程、经过验证的诊断算法、自动治疗系统或已经发布的完整机器可执行本体。

# 术语说明

“功能调用”（functional engagement）是中文“调用”的技术英文表达。它不等于患者参与、服务参与、意识命令、主观意愿、主动配合或单纯神经激活。为避免类型坍缩，本文至少区分四类对象。

**调用模式规格（Engagement-Pattern Specification）**：描述所需人体功能可以通过何种组织方式或轨迹运行的数学或信息对象，记为 \(\sigma\in\Sigma\)。规格本身不是已经发生的身体过程。

**实际调用过程（Actual Engagement Process）**：在具体人、需求、情境和时间中，所需人体功能真实发生的身体运行过程，记为 \(a_{\mathrm{obs}}\)。当证据支持该过程实现了某个调用模式规格时，写为：

\[
a_{\mathrm{obs}}\models\sigma_{\mathrm{obs}}.
\]

**功能调用断言（Functional Engagement Assertion，FEA）**：一个被对象化、携带证据的多元关系实例，把人、需求、所需人体功能、情境、时间区间、实际过程、证据状态、来源和规则版本连接起来。它不能被压缩为一个无条件的二元关系。

**调用模式推断（Engagement-Pattern Inference）**：根据实际调用过程证据形成的可修正分类，例如适当、代偿、受限、未建立或无法确定。推断值不能被当作调用模式规格或实际过程本身。

正式定义保留“被适当调用”（appropriately engaged），因为它承接“正常调用”的规范含义。适当性取决于具体人、需求、情境、时间、安全、代价、可维持性和恢复条件；它不规定唯一理想动作，也不把所有身体划分为普遍的正常与异常二元类别。

本文中的“能力”指依赖身体而存在的人体功能能力。它不等同于分数、测量结果、活动表现、生理过程、器官功能或专业判断。这些对象可以为能力提供证据、实现能力、约束能力或表示能力，但不能被静默地当作能力本身。

# 1. 引言

关于人体的知识已经非常丰富。解剖学表达身体结构；生理学表达维持、调节、适应、防御、修复和恢复过程；医学识别疾病、损伤、病理机制与安全风险；康复研究和恢复活动与参与中的功能；运动科学通过结构化暴露发展能力、耐受、技能与表现；心理、营养、睡眠、行为和环境健康进一步补充解释与干预层。计算生理学、肌骨仿真和数字孪生研究也在尝试跨尺度连接这些知识。

本文面对的问题不是专业知识不足，而是缺少一个足够明确的形式对象，把这些知识围绕同一个具体人连接起来。实验室检查、影像、肌力测试、动作观察、疼痛自述、任务结果和执行记录都可能有效，但它们同时存在，并不自动回答以下问题：

- 当前需求需要什么人体功能；
- 这个人当前具有哪些能力；
- 所需功能是否在实际过程中运行；
- 实际调用是否符合当前个体边界和储备；
- 任务完成付出了什么代价；
- 证据不足时允许推断到什么程度；
- 下一步什么行动安全、合法、合理且值得实施。

ICF 建立了身体功能与结构、活动、参与、环境因素以及能力和表现的国际框架。Physiome、Virtual Physiological Human 和完整人体研究推动多尺度生理模型整合；OpenSim 展示了可复用肌骨模型的价值；数字孪生强调个体状态、持续数据更新与未来模拟。这些工作证明了整合的必要性，但仍需要一个形式接口，把内部身体状态、人体功能能力、具体需求、实际调用、生活结果和长期行动连接起来。

UOHF Definition 2.1 规定：人体功能是身体为满足内部和外部需求而被适当调用的能力。内部需求包括维持、调节、发育、防御、适应、修复与恢复；外部需求包括行为、环境暴露和现实任务。任务因此是外部需求的重要运行化形式，但不是人体功能的全部边界。

本文进一步追问：如果这些承诺要成为一套一致、可扩展、可证伪和面向工程实现的框架，而不是一组语言规则，最低限度需要什么形式结构？

> **本文不把人体功能表示为一个普遍总分，而把它表示为一组绑定于具体人的能力；这些能力是否充分，只有相对于明确的需求、情境、时间、边界和可能调用过程才具有意义。**

本文的主要贡献包括：

1. 建立严格类型系统，区分能力、可能的调用模式规格、实际调用过程、潜在结果、预测结果、观察结果、证据、假设与表示；
2. 引入能力到调用模式的可实现性算子，避免直接求交不同类型的对象域；
3. 定义需求有界可实现性的真实层命题与证据层判断，并给出集合论后果；
4. 提出结果不可识别性命题，说明为什么同一表现不能自动推出唯一原因；
5. 将问题假设与证据状态分开，并建立动态决策和状态更新层；
6. 提出可使框架失败、修正或获得预测和决策效度的实证研究路线。

# 2. 目标、方法与范围

## 2.1 目标

本文旨在规定一套最低形式架构，使人体功能能够在内部与外部需求中被一致表达，并保持现实、证据、推断、表示和行动之间的边界。它需要足够开放，能够接入未来的生理、力学、行为与环境模型；同时需要足够受约束，避免自动因果归因、不安全行动和类型错误。

## 2.2 方法

本文采用概念分析、形式类型分离、本体能力问题、公理化规定、判据构造、反例分析和案例测试。形式陈述分别接受两种验证：

- **内部有效性**：结论能否从定义和公理无矛盾地推出；
- **经验有效性**：变量能否可靠测量、区分相关状态、预测未来结局并改进决策。

形式成立不自动等于经验有效。若映射或测量模型不充分，一条逻辑正确的命题仍可能缺少现实价值。

## 2.3 范围

本文是形式框架和计算架构论文，不是系统综述、临床指南、诊断标准、随机对照试验或完整人体仿真器。本文不宣称：当前 UOHF 能力目录已经穷尽全部人体功能；可以从一个症状计算出唯一病因；或可以脱离专业证据和权限自动选择干预。

本文所说的覆盖是**结构性覆盖**，即相关内容应当拥有明确的类型位置：需求、能力、实现机制、调用过程、结果、测量、假设、边界、行动、变化或明确未知。它不意味着这些内容已经全部被发现、测量或计算。

# 3. 与现有框架的关系

## 3.1 ICF：能力、表现与功能

ICF 对能力与现实环境表现的区分对 UOHF 非常重要。UOHF 不替代这一框架，而是在二者之间增加过程层问题：在具体需求下，哪些人体功能实际运行，通过哪些结构与过程运行，代价多大，边界多窄，以及恢复结果如何。

功能调用不是 ICF performance 的同义词。一个人可能通过代偿、高代价、窄储备、辅助或环境改变完成任务。因此表现可以完成，而人体功能状态不一定正常。

## 3.2 Physiome、完整人体研究与多尺度模型

Physiome 和完整人体研究可以估计或约束身体状态与能力；UOHF 提供需求条件化接口，判断这些能力能否在同一个人身上被适当调用。两者是架构互补，不是学科领地划分。未来完整人体模型可以同时包含生理迁移和任务层人体功能迁移，但必须保留尺度、模型身份、证据和推断范围。

## 3.3 专门仿真模型

OpenSim 等模型可以估计动作、肌肉协调和内部负荷，但单个模型输出不能独立决定完整人体功能。例如关节负荷可以成为结构负担或限制证据；需求是否被适当满足，还取决于更广泛能力、实际调用、持续性、安全边界、恢复和情境。

## 3.4 数字孪生与序贯决策

数字孪生强调个体化状态、重复数据同化、未来模拟和动态决策。UOHF 在此基础上加入领域本体和证据治理：系统必须保存看到了什么、推断了什么、使用了哪个个体状态版本、允许了什么行动，以及行动后真实发生了什么变化。

## 3.5 形式本体与来源治理

OWL、SHACL、PROV-O 等技术可用于实现共享术语、关系约束、图验证和来源追踪，但它们不是人体功能根定义的来源。UOHF 先规定领域中必须保持的类型边界，再选择机器可读技术承接。

UOHF 不声称单独发明了能力—表现区分、人—环境互动、功能实现、任务需求比较、动态更新或本体表示。其更窄的原创主张是：在同一根定义下，受治理地整合个体人体功能能力域、调用模式规格、实际调用过程、事前适当性、潜在—预测—观察结果、明确未知、证据约束归因、受治理行动与长期回写。

# 4. 根定义与形式承诺

## 4.1 根定义

> **人体功能是身体为满足内部和外部需求而被适当调用的能力。**

定义的语法中心是“能力”。人体功能不等同于调用过程，但能力只有相对于可以被适当调用的可能性才获得人体功能意义。能力是依赖身体、绑定于具体人的真实属性，其存在、程度、范围、储备与当前可用性受到身体结构、身体过程、历史、环境与时间影响。

## 4.2 适当性

事前适当调用模式域不能由一个普遍动作模板或人群平均值定义。它必须依赖：具体人、需求、情境、时间、安全限制、当前状态、可用储备、可接受负荷、可维持性、恢复条件，以及必要时个人偏好和环境选项。

适当调用模式域必须在结果观察之前规定，不能因为后来结果良好，就倒推该模式必然适当，否则会形成循环论证。

## 4.3 内部与外部需求

需求是必须通过身体组织得到满足的要求。内部需求包括维持、调节、发育、防御、适应、修复和恢复；外部需求包括行为、环境暴露和现实任务。任务是目标导向的活动或活动情境；任务需求是在具体负荷、速度、工具、环境和个体条件下由任务产生的外部要求。

## 4.4 与早期任务中心定义的关系

早期 UOHF 对外部任务的运行口径——在明确安全约束下，以稳定、有效并且代价有界的方式完成任务——应当被理解为外部需求的一类操作判据，不是第二个根定义。任务—能力匹配（TCM）是外部任务运行化的规则族，不是人体功能的全部方程，也不能替代对人、需求、情境、时间、调用、代价、边界和恢复的完整表达。

# 5. 形式对象与类型系统

令人员、需求、情境和时间的对象域分别为 \(P,D,K,T\)。本文使用以下核心对象，任何对象不得被静默替换为另一对象。

| 符号 | 形式角色 | 类型边界 |
|---|---|---|
| \(p\in P\) | 具体的人 | 不同人相同测量值不自动表示相同状态或边界 |
| \(d\in D\) | 明确的内部或外部需求 | 任务只是外部需求的特化 |
| \(k\in K\) | 条件与情境 | 包括环境、负荷、工具、辅助与相关个人条件 |
| \(t\in T\) | 时间点或时间区间 | 能力、边界和调用可随时间变化 |
| \(X_t\) | 潜在或模型化的完整人体状态 | 不可被完整直接观察，可跨生理、结构、认知、行为与恢复尺度 |
| \(H_t\) | 相关历史 | 包括暴露、疾病、损伤、行动、适应、恢复与历史状态版本 |
| \(\mathcal C_t^{\mathrm{real}}\) | 真实人体功能能力域 | 现实中存在但不能作为完整集合直接观察 |
| \(\widehat{\mathcal C}_t\) | 证据支持的能力估计 | 可修正的认识对象，不等同于真实能力域 |
| \(Q(d,k)\) | 需求或调用要求说明 | 规定在该需求和情境下必须组织什么 |
| \(\Sigma\) | 调用模式规格空间 | 包含可能的组织或轨迹规格，不含已经发生的过程 |
| \(\sigma\in\Sigma\) | 一个调用模式规格 | 可能可实现、不可实现、适当或不适当 |
| \(\Gamma_\Sigma\) | 能力到模式可实现性算子 | 把能力与状态映射为当前可实现的调用模式规格集合 |
| \(\Sigma_t^{\mathrm{real}}(p,d,k)\) | 真实可实现模式规格集 | 其中成员仍是规格，不是实际过程 |
| \(\mathcal A_{\mathrm{pre}}^\Sigma(p,d,t,k)\) | 事前适当调用模式域 | 在结果观察前满足个体、安全、负荷、维持与恢复约束 |
| \(\mathrm{Access}_t(\sigma\mid p,d,k)\) | 操作可达性与可靠性 | 防止理论可行但无法重复或实际不可达的模式被视为满足需求 |
| \(a_{\mathrm{obs}}\) | 有证据支持实际发生的调用过程 | 发生中的身体过程，不等同于模式规格 |
| FEA | 功能调用断言 | 绑定人、需求、功能、情境、时间、过程、证据与版本的对象化关系 |
| \(J_{\mathrm{eng}}\) | 调用模式推断 | 适当、代偿、受限、未建立、无法确定等可修正分类 |
| \(E_t^{\mathrm{pot}}(\sigma)\) | 潜在结果关系 | 在指定状态和条件下执行规格可能兼容的结果集合 |
| \(\widehat E_t(\sigma)\) | 预测结果 | 基于当前证据的可修正预测 |
| \(E_t^{\mathrm{obs}}\) | 观察到的实际反应 | 包括需求达成、表现、代价、负担、边界、储备、维持与恢复证据 |
| \(Y_t\) | 证据与测量结果 | 观察、自述、测试、设备和资料产生的信息 |
| \(Z_t^{\mathrm{problem}}\) | 问题或限制因素假设集 | 可并存多个解释 |
| \(S_t^{\mathrm{evidence}}\) | 证据状态 | 支持、减弱、矛盾、未评估、证据不足或无法确定 |
| \(\Pi_t\) | 证据条件化信念状态 | 对支持和不确定性的受治理表示；概率不是默认前提 |
| \(U_t\) | 受治理行动域 | 包括观察、评估、环境调整、暂停、转介、治疗、康复、运动与监控 |

## 5.1 潜在状态与可观察证据

完整身体状态不能被直接完整观察。一般观察模型可写为：

\[
Y_t=O(X_t,\mathrm{procedure},\mathrm{conditions},\varepsilon_t),
\]

或概率形式：

\[
Y_t\sim P_O(\cdot\mid X_t,\mathrm{procedure},\mathrm{conditions}).
\]

它可以承接数值、等级、分类、文本、自述、图像、设备时间序列和缺失数据，而不假定误差一定可加。底层状态、采集过程、结果、解释和版本化表示必须保持分离。

## 5.2 真实能力支持与证据能力估计

\[
\mathcal C_t^{\mathrm{real}}=\Phi_{\mathrm{ontic}}(X_t,H_t),
\qquad
\widehat{\mathcal C}_t=\Phi_{\mathrm{epistemic}}(Y_{0:t}).
\tag{1}
\]

\(\Phi_{\mathrm{ontic}}\) 表示能力在现实中对身体状态和历史的依赖；\(\Phi_{\mathrm{epistemic}}\) 表示系统根据证据形成能力估计。二者不是一个普遍数值公式。系统只能基于证据估计采取行动，不得把估计默认为已经完整访问真实能力域。

## 5.3 能力到调用模式的可实现性

能力域不能与实际过程域直接求交，因为二者包含不同类型的实体。本文引入规格空间 \(\Sigma\) 和可实现性算子 \(\Gamma_\Sigma\)：

\[
\Sigma_t^{\mathrm{real}}(p,d,k)
=
\Gamma_\Sigma\!\left(\mathcal C_t^{\mathrm{real}},X_t,d,k\right).
\tag{2}
\]

一个规格可以可实现但不适当、不安全、代价过高、不可稳定达到或无法维持；一个理论上适当的规格，也可能因当前能力不足而不可实现。只有 \(a_{\mathrm{obs}}\) 是实际发生的调用过程。

## 5.4 事前适当调用模式域

\(\mathcal A_{\mathrm{pre}}^\Sigma(p,d,t,k)\) 必须独立于观察结果定义，以避免循环推理。它包括在决策点之前或当时可以支持的安全、需求、专业限制、当前边界、可接受负荷和维持—恢复约束。一次后来成功的结果不能反过来自动证明模式事前适当。

## 5.5 潜在、预测和观察结果

本文区分三类结果：

- \(E_t^{\mathrm{pot}}(\sigma\mid X_t,d,k)\)：真实层面的兼容潜在结果集合；
- \(\widehat E_t(\sigma)\)：执行前的模型预测；
- \(E_t^{\mathrm{obs}}=e_{\mathrm{obs}}(X_t,a_{\mathrm{obs}},d,k)\)：实际过程发生后有证据支持的观察反应。

最低反应向量可以包括需求达成、表现、即时代价、累积负担、边界余量、储备、可维持性、做后反应和恢复。维度可以按领域扩展，但潜在、预测和观察结果不能坍缩成一个对象。

# 6. 核心公理

| 公理 | 内容 |
|---|---|
| A1 人员绑定 | 每条人体功能断言必须绑定具体人或明确定义的人群类型；个体推断不得静默跨人迁移 |
| A2 需求绑定 | 能力充分性、调用、代价和边界断言必须绑定明确的内部或外部需求 |
| A3 情境与时间绑定 | 同一人和同一需求在不同情境或时间可以具有不同可实现性和调用结果 |
| A4 类型分离 | 能力、模式规格、实际过程、潜在结果、预测结果、观察反应、证据、假设、证据状态、表示与行动是不同类型 |
| A5 可实现性中介 | 能力通过显式算子影响可实现模式规格；能力、规格和实际过程域不得直接求交 |
| A6 事前适当性 | 适当调用模式域不得使用同一个事后结果反向定义 |
| A7 开放世界证据 | 缺少证据不能建立能力不存在、调用未发生或某病因成立的否定事实 |
| A8 非唯一归因 | 表现或测量结果不能唯一识别限制因素，除非可识别性被独立证明 |
| A9 安全、权限与证据门控 | 每种行动具有最低证据阈值；安全、权限、同意、范围或证据不足时，不得执行高后果行动；信息采集行动可因证据不足而被允许 |
| A10 长期修正 | 状态推断和行动策略必须能被新证据、实际变化、复评与版本化回写修正 |
| A11 锚点非因果 | 结构或过程锚点只表示实现、负担、观察或约束关系，不能单独断言因果病理 |
| A12 明确未知 | 当前本体、测量模型或证据不能支持判断时，未知是有效正式结果 |

这些公理规定的是表示与推理治理条件，不证明某一测试工具必然有效，也不证明某一因果模型必然正确。

# 7. 需求有界可实现性

## 7.1 定义

令 \(\mathrm{DHR}^{\mathrm{ontic}}(p,d,t,k)\) 表示：在指定时间与情境下，该需求对这个人而言在真实层面可以被适当地满足。它不是人体功能本身，也不是运行时判断，而是关于当前能力是否支持至少一个可达、可靠、事前适当并具有可接受潜在结果的调用模式规格的命题。

\[
\begin{aligned}
\mathrm{DHR}^{\mathrm{ontic}}(p,d,t,k)=1
\iff {} & \exists\,\sigma\in
\Sigma_t^{\mathrm{real}}(p,d,k)
\cap
\mathcal A_{\mathrm{pre}}^\Sigma(p,d,t,k)\\
& \mathrm{Access}_t(\sigma\mid p,d,k)\ge r_{\min}
\quad\text{且}\quad
E_t^{\mathrm{pot}}(\sigma)\cap
\mathcal E^*(p,d,t,k)\ne\varnothing .
\end{aligned}
\tag{3}
\]

其中 \(\mathcal E^*(p,d,t,k)\) 为在该人、需求、时间和情境下可接受的结果集合。

## 7.2 判据解释

需求有界可实现性成立，当且仅当至少存在一个调用模式规格：

1. 能由该人当前真实能力与状态实现；
2. 属于该人的事前适当调用模式域；
3. 在受限扰动下具有达到最低要求的可达性和可靠性；
4. 其潜在结果集合至少与一个可接受结果相交。

运行系统不能直接观察完整真实集合，因此只能输出：

\[
\widehat{\mathrm{DHR}}_t
\in
\{\mathrm{supported},\mathrm{not\ supported},\mathrm{insufficient\ evidence}\}.
\]

式（3）是对真实层命题的定义，不是已经发现的普遍生物学定律，也不是一个非平凡定理。它的科学价值取决于各对象能否在不循环的情况下被运行化和验证。

## 7.3 空可接受模式后果

**命题1：** 如果不存在同时满足可实现、事前适当、可达可靠和潜在结果可接受的 \(\sigma\)，则：

\[
\mathrm{DHR}^{\mathrm{ontic}}(p,d,t,k)=0.
\]

**证明：** 判据要求至少存在一个满足全部条件的规格。若不存在，该存在量词为假，因此 DHR 为0。某个实际过程即使部分完成任务，也不能使上述合取条件自动成立。□

但如果系统只是无法确定这些集合是否相交，正确输出应当是“证据不足”，而不是把真实层命题判为0。

## 7.4 硬门控与不可补偿性

安全要求、关键调用要求和最低可靠性可以构成硬约束。一个维度上的高表现不能平均抵消关键安全失败；不可缺少的调用要求不能被无关能力补偿；一次偶然成功也不能建立稳定可达性。因此人体功能不能被还原为无约束加权总分。

## 7.5 人级结构化状态向量

需求有界可实现性应与结构化状态向量共同报告，而不是只输出一个总分。最低维度包括：需求达成、调用质量、即时代价、累积负担、边界余量、储备、可维持性、恢复和不确定性。正常、代偿、临界和失能是对这些证据的摘要，不是对所有器官、细胞和分子过程的普遍标签。

# 8. 问题假设与证据状态

\[
Z_t^{\mathrm{problem}}\subseteq\{Z_C,Z_A,Z_O\},
\qquad
S_t^{\mathrm{evidence}}\in
\{\mathrm{supported},\mathrm{weakened},\mathrm{contradicted},\mathrm{not\ assessed},\mathrm{insufficient},\mathrm{undetermined}\}.
\]

框架使用两个相互独立的轴：

- \(Z_C\)：能力覆盖失败；
- \(Z_A\)：功能调用困难；
- \(Z_O\)：其他或残余解释。

一个案例可以同时属于多个问题假设类，“混合”不是第四个原始问题类型。证据不足是认识状态，不是人体功能问题类型。

**能力证据不能由任务结果替代。** 疼痛或失败不能单独证明能力缺失。它也可能来自需求过高、环境限制、保护性调用、疾病、疲劳、既往暴露或测量误差。首先应当判断在指定需求下是否存在能力覆盖失败；进一步声称能力损伤，需要独立能力证据和明确参照。

**调用不能由缺失断言反推。** 没有功能调用断言不等于功能没有运行。开放世界语义要求正面与负面断言都必须有明确证据。

**代偿是一种关系，不是自动缺陷。** 代偿表示身体相对于另一条可用或预期路径改变了组织方式。它可以保护、必要、高效、临时、高代价或有害，必须结合人、需求、情境、边界与时间判断。

# 9. 结果不可识别性与因果假设

## 9.1 结果不可识别性命题

\[
e(X_1,a_1,d,k)=e(X_2,a_2,d,k)=y,
\qquad
(X_1,a_1)\ne(X_2,a_2)
\Longrightarrow
y\not\Rightarrow(X,a)_{\mathrm{unique}}.
\tag{4}
\]

**命题2：** 如果结果映射 \(e\) 在相关潜在状态与调用过程中不是单射，则观察结果 \(y\) 不能唯一识别一个底层状态—调用配置，也不能单独建立唯一原因或限制因素。

**证明：** 非单射意味着至少存在两个不同输入对 \((X_1,a_1)\) 与 \((X_2,a_2)\)，在相同需求和情境下产生相同结果 \(y\)。因此 \(y\) 的逆像含有多个状态—调用配置，单凭 \(y\) 不能逻辑推出唯一底层状态或过程；唯一因果归因必须依赖额外证据和独立成立的因果模型。□

疼痛、不稳、速度下降、疲劳和任务失败都是典型逆问题。同样的爬楼膝痛可以来自不同人的近期负荷增加、负荷耐受下降、局部敏感、疾病、疲劳、环境条件、保护性调用或它们的组合。

## 9.2 信念状态与证据收束

\[
\Pi_t
=
\mathrm{BeliefState}\!\left(Y_{0:t},D_{0:t},K_{0:t},U_{0:t-1}\right).
\tag{5}
\]

\(\Pi_t\) 是对可能状态和假设的证据条件化信念状态，不默认等于概率分布。当前可使用支持、减弱、矛盾、未评估、证据不足和无法确定等治理状态。只有在先验、似然、依赖关系、观察模型和人群校准得到验证以后，才能进一步使用数值概率；在此之前不得生成伪精确百分比。

## 9.3 因果推断需要更强设计

假设排序不等于因果证明。因果主张需要合理研究设计、时间顺序、机制支持、替代解释排除、自然实验、受控扰动或其他有效因果方法。行动后改善可以增强原假设支持，但不能唯一证明原假设，因为自然波动、均值回归、共同干预、期待、适应和测量变化也可能贡献结果。

## 9.4 结构锚点不是诊断

结构锚点可以表示能力在哪里实现、承担、受约束或被观察，但不能推出该结构是表现的唯一原因。正确链条应为：

> 需求 → 所需人体功能 → 调用证据 → 结果与代价 → 限制因素假设 → 收束性评估 → 当前主问题。

除非有独立证据，禁止从疼痛位置直接跳到结构病理。

# 10. 锚点、评估与受治理行动

## 10.1 六类锚点

| 锚点类型 | 回答的问题 | 例子 |
|---|---|---|
| 人体功能能力锚点 | 当前需要、具备、缺少或未运行的是哪项能力 | 产力、负荷耐受、平衡、吞咽、沟通、恢复 |
| 身体结构锚点 | 哪些解剖结构实现、承担或约束该能力 | 膝区、伸膝装置、气道、血管结构 |
| 生理或身体过程锚点 | 哪些过程实现、调节或约束能力 | 心肺调节、感觉整合、免疫修复、自主恢复 |
| 观察或评估锚点 | 哪个程序最能区分当前假设 | 任务观察、分级负荷、检查、仪器测量、重复追踪 |
| 约束锚点 | 当前在检验什么边界或限制条件 | 安全限制、活动范围、负荷阈值、恢复延迟、环境障碍 |
| 行动锚点 | 什么经授权行动可以改变状态或增加信息 | 降负荷、康复任务、运动进阶、转介、暂停、环境改变 |

评估属于认识层。它通过明确采集条件产生证据，其价值取决于可靠性、效度、安全性、区分假设的能力和对当前需求的相关性。评估不因命名而改变人的现实。

行动域不仅包括治疗和训练，也包括观察、补充评估、改变需求条件、环境调整、辅助、降低暴露、暂停、医学转介、康复、运动、教育、恢复支持与监控。

# 11. 动态决策与长期更新

## 11.1 受治理行动选择

当前 UOHF 运行层首先需要规则约束的选择接口，而不是未经校准的数值优化器：

\[
\begin{aligned}
u_t=\mathrm{Select}_{\mathcal R}(&\,\mathrm{safety},\mathrm{authority},\mathrm{consent},
\mathrm{EvidenceThreshold}(u),\\
&\,\mathrm{hypotheses},\mathrm{evidence\ status},\mathrm{feasibility},
\mathrm{stop\ conditions},\mathrm{reassessment}).
\end{aligned}
\tag{6}
\]

式（6）表示当前行动选择合同，不宣称数值最优。未来只有在因果图、干预效应、结果尺度、权重和干预数据得到明确验证后，才可以进入期望人体功能价值、风险、成本、可行性和信息增益的优化。

## 11.2 动态状态迁移

\[
X_{t+1}=F(X_t,D_t,a_t,u_t,K_t,H_t,\omega_t),
\qquad
\Pi_{t+1}=\mathcal B(\Pi_t,Y_{t+1},E_{t+1},u_t).
\tag{7}
\]

\(F\) 表示人本身的实际变化；\(\mathcal B\) 表示模型在新证据进入后修正信念和版本化表示。二者不得混淆：人可以变化但没有被测到，记录也可以改变而人没有变化。

序贯决策、动态治疗策略和部分可观察马尔可夫决策过程提供相关数学方法，但 UOHF 不要求所有实现都必须成为 POMDP。它们说明了为什么状态、历史、行动、观察和不确定性必须分开表达。

```mermaid
flowchart LR
    D[需求与情境] --> X[完整人体状态 X_t]
    X --> C[真实能力域与能力估计]
    C --> S[可实现调用模式规格]
    S --> A[事前适当调用模式域]
    A --> P[潜在与预测结果]
    P --> U[受治理行动选择]
    U --> O[实际调用过程 a_obs]
    O --> R[观察反应 E_obs]
    R --> Y[证据 Y_t]
    Y --> B[信念、假设与证据状态]
    B --> CH[实际变化、复评与回写]
    CH --> X
```

一个模式规格可以可实现且适当但尚未发生；只有 \(a_{\mathrm{obs}}\) 是实际过程。预测结果和观察结果必须保持分离。

# 12. 示例：爬楼膝痛

设 \(p\) 为一个在爬楼时报告膝痛的人，\(d\) 为在指定楼梯和情境 \(k\) 下产生的外部需求。情境应包括台阶高度、速度、扶手、携带负荷、鞋、疲劳和重复次数。

初始自述只能建立“爬楼需求情境中出现膝痛”这一表现事实。它可以进一步记录时间、位置、强度、从第几级出现、做后反应和次日变化，但不能自动建立能力缺陷、调用问题、结构损伤或唯一疼痛来源。

爬楼需求可能涉及下肢产力、负荷耐受、关节活动、单腿支撑、姿势控制、感觉整合、协调、心肺耐受、重复任务耐受和恢复。任务—功能关系只能提供候选所需功能，不能宣布每项能力受损。

| 假设 | 可能支持证据 | 区分性证据 |
|---|---|---|
| \(Z_C\)：指定需求下能力覆盖失败 | 台阶高度、负荷或重复量超过稳定阈值后重复出现疼痛或失败，且独立能力证据低于需求 | 分级台阶任务、产力和耐受评估、做后与次日反应 |
| \(Z_A\)：能力存在但实际调用不适当 | 独立证据支持能力存在，任务观察发现可修改调用模式，改变速度、提示或情境后反应变化 | 任务观察、条件对照、速度或提示操控、向其他任务迁移 |
| \(Z_C+Z_A\) | 能力覆盖和实际调用均受限 | 能力证据、任务证据及长期响应联合验证 |
| \(Z_O\)：医学或局部组织因素 | 当前能力与调用证据不能解释表现，或存在安全线索 | 病史、检查、风险筛查及有指征时的医学资料 |
| \(Z_O\)：恢复、暴露、环境或行为 | 表现与近期负荷增加、恢复不足或情境关联强于稳定能力缺陷 | 暴露史、睡眠与恢复、工作负荷、时间序列 |
| 证据不足 | 当前资料不能区分候选 | 继续收集任务、能力、调用、代价、边界和恢复证据 |

锚点推导顺序应为：需求 → 所需功能 → 候选调用模式规格 → 实际调用证据 → 表现、代价、边界与恢复 → 问题假设与证据状态 → 观察、约束、过程和结构锚点 → 受治理行动。

下一步可能是补充评估、暂时调整爬楼剂量、使用扶手、分级能力暴露、任务康复、调用重组、恢复调整、医学转介或监控。选择取决于证据、安全、权限、可行性和信息价值。行动后改善会更新假设支持和个体状态，但不能倒推唯一历史病因。

## 12.1 内部需求示例：运动后恢复

设 \(d_{\mathrm{int}}\) 为完成一次明确运动暴露后恢复心肺、代谢、体温和自主调节稳定的内部需求。候选能力锚点包括循环调节、通气、能量供应、体温调节和恢复调节。调用模式规格描述可能的协调恢复轨迹；实际调用过程是身体真实发生的恢复过程。

心率、呼吸、疲劳、体温、症状和恢复时间是表现或观察，不是唯一原因。恢复延迟可支持需求剂量过高、恢复能力不足、疾病、炎热、补液、药物或测量误差等不同假设，并分别记录证据状态。允许行动可以是休息与监控、调整需求剂量、补充评估或医学转介。

# 13. 从形式框架到 UOHF 实现架构

## 13.1 UOHF

UOHF 定义并治理领域对象、关系、约束、证据要求、权限规则、来源、版本和生命周期。它不是静态术语表。形式框架赋予需求、人体功能、调用、表现、代价、边界、状态、行动与反馈之间的运行含义。

## 13.2 人体功能引擎

人体功能引擎执行受边界约束的推理和行动流程：识别所需功能、检查证据、区分能力—模式规格—实际过程、保留未知、执行安全和权限门控、形成问题假设及其证据状态、选择允许的下一步，并生成可追溯推理记录。AI候选输出不得静默转化为正式事实。

## 13.3 个人人体功能模型

个人人体功能模型保存一个人的版本化长期状态记忆：经历过的需求、得到证据支持的能力、考虑过的模式规格、观察到的实际调用过程、预测和观察结果、表现、代价、边界、行动、实际变化和未解决不确定性。历史状态必须能够回放，不能被最新解释覆盖。

## 13.4 人体功能世界模型

人体功能世界模型表达需求、情境、时间、暴露、内源性调节和外部行动条件下的可能状态迁移。模式规格、潜在结果、预测未来、当前推断状态、实际过程和观察事实必须保持不同类型。领域生理与力学模型可以通过明确接口组合，同时保留尺度、标识、假设与验证状态。

## 13.5 功能调用断言的机器实现

未来 OWL 实现应把 FunctionalEngagementAssertion 建模为关系对象，至少连接：hasPerson、hasDemand、requiresHumanFunction、hasContext、hasTimeInterval、supportedByActualProcess、instantiatesPatternSpecification、hasEngagementInference、hasEvidenceStatus、generatedByAssessment、hasProvenance 和 usesRuleVersion。正面和负面断言必须明确；没有断言既不推出正面，也不推出负面。SHACL 或等价验证层应检查必填字段、值域、来源和生命周期。

# 14. 科学研究路线

形式框架只有在变量与算子被运行化并与更简单模型比较后，才具有科学价值。

| 阶段 | 核心工作 | 最低成功标准 |
|---|---|---|
| 1 形式规定 | 编码类型、关系、公理与约束，测试一致性和能力问题 | 无类型矛盾；未知可保留；推理可复现 |
| 2 内容效度 | 专家和利益相关者审查需求、能力、调用、代价、边界与恢复 | 这些构念被认为必要、可区分、可理解 |
| 3 运行化 | 为单一有界需求建立测量程序和证据包 | 每个变量有可观察或明确潜在状态与采集协议 |
| 4 可靠性 | 检验评估者间、评估者内、重测与数据质量 | 达到预设可靠性阈值并报告误差 |
| 5 构念效度 | 检验能力、调用、代价、边界和恢复是否经验可分 | 因子、聚合、区分与已知组证据 |
| 6 预测效度 | 与疼痛分数、单项能力或普通专业判断比较 | 样本外预测任务持续、恶化、恢复或升级 |
| 7 决策效用 | 检验模型指导是否改善安全、效率、结果或信息增益 | 前瞻比较或自适应行动研究 |
| 8 泛化 | 跨需求、人群、专业场景、语言和数据源重复 | 核心关系稳定，测量扩展允许领域差异 |

第一项可辩护的研究不应试图一次验证完整人体系统，而应选择一个有界需求，例如爬楼，检验能力、调用、反应代价、边界和恢复能否被不同测量区分，并比较其对重复任务耐受和短期恢复的预测是否优于单独肌力、疼痛分数和普通判断。

对于 AI，可建立审计基准：是否区分观察与推断、是否保留证据不足、是否避免症状直跳结构、是否选择区分性证据、是否遵守安全权限门控、以及在矛盾反馈后是否修正结论。

# 15. 可证伪条件

以下不是普通实现缺陷，而是可能推翻或迫使核心主张缩小的结果：

| 失败条件 | 科学含义 |
|---|---|
| 能力与调用无法被经验区分 | 若严格研究中二者始终坍缩为同一因子，其独立区分可能缺少经验价值 |
| 模型不优于简单基线 | 若疼痛、单项能力或普通判断以更低成本达到同等预测，复杂度在该用途下不成立 |
| 适当性只能循环定义 | 若适当调用域只能由同一个事后结果定义，核心判据不可用 |
| 评估者间判断不稳定 | 若受训人员不能重复能力、调用、边界和状态判断，构念尚未被充分运行化 |
| 轻微情境变化使规则失效 | 若人、需求、时间、情境、可达性与可靠性不能解释变化，形式变量不完整 |
| 锚点持续诱发错误因果归因 | 若实现仍系统性把结构当病因，治理主张失败 |
| 未知无法被保留 | 若系统强迫所有案例进入已知类别，开放世界和安全主张失败 |
| 长期更新不能透明修正历史 | 若新证据覆盖历史或无法解释判断变化，可审计性未实现 |

一个领域中的负面结果不自动推翻根定义，但可以推翻具体测量模型、能力目录、调用规则、状态分类器或行动策略。框架必须允许局部失败和版本修正，而不是保护所有组成部分不受反证。

# 16. 讨论

本文的新意不在于单独提出“需求必须由能力覆盖”。其独特结构是：在同一根对象下，将人体功能能力、调用要求、可实现模式规格、事前适当模式、操作可达性、实际调用过程、潜在—预测—观察结果、表现、测量、代价、边界、储备、问题假设、证据状态、受治理行动、实际变化、反馈与版本化状态表示分开后重新连接。

一个总分可以用于筛查或传播，但不能作为基础表示。人体功能维度异质，关键安全条件不可补偿，同分个体也可能具有不同需求、边界、调用路线和风险。任何总分都必须可追溯到结构化向量，并保留未知和硬门控失败。

这套框架能够为医学、康复和运动提供共同解释而不抹平专业边界：医学主要处理人体功能能力、生物学基础与安全边界；康复主要让所需能力重新进入现实需求中的事前适当调用模式；运动通过持续、适当、渐进的调用维护和增强人体功能并扩展调用边界。这些是主要组织方向，不是排他的职业范围。

本文不是完整人体方程。可计算的完整人体系统需要大量局部与多尺度模型。UOHF 的作用是提供稳定的顶层语义和决策接口，使这些模型能够共同进入同一个人的需求条件化人体功能状态。完整覆盖意味着可扩展的结构闭合和明确未知，不意味着已经提前拥有全部生物变量。

本文立即形成的科学问题包括：能力加调用证据是否比能力单独更能预测任务结果；高代价完成能否与正常人体功能区分；情境扰动能否区分能力限制与调用限制；人级状态能否预测后续恶化或恢复；结构化 AI 能否减少无证据因果归因。

---

# 17. 局限

1. 当前数学对象仍是形式占位符，直到各领域测量模型被定义；\(\Gamma_\Sigma\)、\(\mathcal A_{\mathrm{pre}}^\Sigma\)、\(\mathrm{Access}_t\)、\(E_t^{\mathrm{pot}}\)、\(\widehat E_t\)、\(F\) 和 \(\mathcal B\) 都不是已校准的普遍函数。
2. 当前人体功能能力目录和关系拓扑未被证明完整，新的能力、需求、关系与状态维度可能要求增删或拆分。
3. 适当性包含规范性与个体性约束，必须透明治理，不能完全交给统计优化。
4. 完整人体潜在状态只能被部分观察，推断将长期存在不确定性，缺失也可能不是随机的。
5. 因果归因本身困难；行动后的重复反应可以增强证据，但不能保证唯一识别。
6. 爬楼案例仅用于逻辑示例，不证明膝痛诊断或治疗效度。
7. 与 ICF、SNOMED CT、UMLS、BFO、生理模型库和未来完整人体标准的互操作需要显式映射与外部审查；标签相似不等于等价。
8. 本文由同时开发相关本体、软件、培训和服务的机构完成，需要独立重复与治理。
9. 需求有界可实现性判据是定义性判据；只有其运行化能够产生可靠测量、区分性分类、优于简单基线的预测和有益决策时，才获得经验科学价值。

---

# 18. 结论

本文在不把人体功能还原为症状、单项测量、任务结果或总分的前提下，对其进行了形式化。人体功能仍然是身体为满足内部和外部需求而被适当调用的能力。能力、调用模式规格、实际调用过程与结果彼此相关，但在本体上不同。

能力通过调用模式规格上的可实现性算子与明确需求发生关系；事前适当性和操作可达性限制哪些规格能够支持需求；潜在和预测结果必须与实际过程发生后的观察反应分开。

需求有界可实现性判据规定了当前能力何时在真实层面能够适当地满足一项需求，以及运行系统能够形成的独立证据判断。结果不可识别性命题说明了为什么疼痛、表现改变和任务失败不能单独揭示唯一原因。问题假设可以包括能力覆盖失败、调用困难和其他残余解释；证据状态则分别记录支持、减弱、矛盾、未评估、不充分或无法确定。

形成的架构是动态的：证据更新信念状态；行动在安全、同意、权限、可行性、停止和复评约束下选择；实际变化与模型更新保持区分；全部结论版本化、可修正、可回放。这为 UOHF、本体化人体功能引擎、个人人体功能模型和人体功能世界模型提供了一个面向实现的候选形式内核。

> **核心科学主张不是一条方程已经计算完整人体，而是所有有效人体功能知识都应当能够在不改变根定义的前提下，进入同一套类型明确、需求条件化、证据有界、安全受约束并可长期修正的计算框架。**

这套框架能否成为有效科学，最终取决于运行化和比较证据：构念必须可测，判断必须可重复，预测必须优于简单替代方案，决策必须产生实际效用，失败必须透明。

2. 满足该需求需要哪些人体功能？
3. 当前哪些能力得到支持、被矛盾证据削弱或尚未评估？
4. 哪些调用模式规格可以由当前能力和状态真实实现？
5. 哪些规格在当前安全、负荷、维持和恢复约束下事前适当且达到所需可靠性？
6. 哪个实际调用过程得到证据支持，它实现了哪个规格，哪些 FEA 成立，什么调用推断仍可被支持？
7. 哪些内容属于观察、自述、测量、推断、预测或表示？
8. 当前支持什么即时代价、累积负担、边界和储备？
9. 哪些问题假设仍然合理，各自证据状态是什么，什么证据最能区分它们？
10. 当前什么行动安全、有权、在范围内、达到行动特异证据阈值且值得实施？
11. 需求、暴露、内源调节或外部行动以后真实发生了什么变化？
12. 个体模型需要修正什么，同时必须保留哪一历史状态？

# 附录B：未来机器可读实现的最低要求

- 具体人在具体时间具有具体人体功能能力，并携带证据与不确定性元数据；
- 具体需求在明确情境下需要具体人体功能；
- 调用模式规格、可实现性断言、事前适当性、操作可达性和实际调用过程必须作为不同类型表示；
- FunctionalEngagementAssertion 必须对象化并绑定人、需求、功能、情境、时间、实际过程、证据、来源与规则版本；
- 正面和负面断言明确表示，缺失数据不推出任何一方；
- 潜在结果、预测结果、观察反应、表现和测量结果分别表示；
- 问题假设和证据状态使用两个独立轴；多假设并存用多重成员关系表示；
- 结构、身体过程、观察、约束和行动锚点使用不同关系类型；
- 即时代价、累积负担、边界、储备、可维持性和恢复分别表示；
- 行动记录证据阈值、安全门控、权限、同意、理由、可行性、停止条件、执行事实和复评触发；
- 状态推断必须版本化，并可追溯到准确的本体、规则、证据快照、执行者或模型和生命周期状态；
- 未来 OWL/SHACL 发布应提供稳定 IRI、domain/range、基数约束、shapes、能力问题、示例实例和验证结果；本文本身不构成该机器可执行发布。
