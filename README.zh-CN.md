## UOHF 解决什么问题

医学、生理学、康复、运动训练、行为、环境和个人健康记录都在描述同一个人，但这些系统并不会自动形成一个共同、持续、可计算的人体功能对象。

UOHF 把**人体功能**确立为这一共同对象，并建立受治理的语义与规则基础，用于持续回答：

- 当前存在什么内部需求或外部需求；
- 身体必须组织什么才能满足需求；
- 身体实际上如何被调用；
- 哪些内容属于观察、报告、测量或推断；
- 当前承担了什么代价和累积负担；
- 边界在哪里，余量还剩多少；
- 当前证据支持什么人体功能状态；
- 允许采取什么行动；
- 时间、暴露、调节或行动以后实际发生了什么变化。

UOHF 的目标不是替代任何专业，而是让跨专业人体功能判断变得：

> **可计算、可约束、可追溯、可审计、可修正、可持续更新。**

## UOHF 与普通知识图谱有什么不同

UOHF 不是术语表、普通知识图谱、医学诊断系统或黑箱推荐模型。

它明确区分：

- 需求与需求说明；
- 任务与任务需求；
- 调用要求与实际调用过程；
- 实际调用过程与调用推断、调用表示；
- 实际反应与表现、测量结果；
- 即时代价与累积负担；
- 边界与储备；
- 人体功能状态与状态推断、状态表示；
- 内源性调节与受治理的外部行动；
- 实际变化与反馈信息。

现实对象、证据、推断和信息表示必须分开，这是 UOHF 支持可审计 AI 和高风险决策治理的基础。

## 核心架构

```mermaid
flowchart LR
    D[内部或外部需求] --> ER[调用要求]
    ER --> REP[所需调用过程类型]
    REP --> AEP[实际调用过程]
    AEP --> AR[实际反应]
    AR --> E[表现与测量]
    E --> C[代价、负担、边界与储备]
    C --> SI[状态推断与表示]
    SI --> G[外部行动 / 内源调节 / 时间 / 暴露]
    G --> AC[实际变化]
    AC --> F[新证据与反馈]
    F --> R[复评与版本化回写]
    R --> SI
```

UOHF Definition 2.1 区分四个相互连接的组成部分：

1. **UOHF**：受治理的本体与语义规则层；
2. **人体功能引擎**：受边界约束的运行推断与回写层；
3. **个人人体功能模型（IHFM）**：一个人的长期状态记忆；
4. **人体功能世界模型（HFWM）**：时间与行动条件下的状态迁移建模层。

> **受治理本体拓扑 → 人体功能引擎 → 个体长期模型 → 人体功能世界模型**

## 当前运行重点

当前实现最强的部分是现实任务判断与长期服务闭环：

> **安全边界 → 任务与情境 → 任务需求 → 所需调用 → 实际调用 → 表现与测量 → 代价与边界 → 限制因素假设 → 证据收束 → 主矛盾 → 状态 → 受治理行动 → 执行 → 实际变化 → 反馈 → 复评 → 回写**

当前使用四类人级任务中心状态：

- 正常状态；
- 代偿状态；
- 临界状态；
- 失能状态。

这些状态不是医学诊断、永久标签，也不是器官、细胞或分子过程的通用状态分类。

## 当前边界

当前受治理实现已经支持概念域、稳定标识符、类型化关系、关系合同、证据结构、权限约束、生命周期治理、任务中心状态收束、行动语义、执行反馈、复评与长期监控。

完整生产本体、关系拓扑、运行规则和业务数据资产不会全部公开复制到本仓库。

UOHF Definition 2.1 当前不宣称：

- 已完成 BFO 全面符合；
- 已完成 OWL 公理化；
- 已建立通用生理状态分类；
- 已形成外部专家共识；
- 已完成临床结局验证；
- 已完成分子到整个人的统一仿真；
- 可以自动诊断或自动治疗。

内部需求运行化和多尺度建模仍属于持续研究、形式化与验证工作。
